## Folder Layout

```
src/
  index.html        The page template (webpack adds the script)
  css/styles.css    All styling (imported by index.ts, so webpack bundles it)
  static/           Copied to the build unchanged, at the same paths
    data/           words.txt, puzzles.txt, LICENSE-wordlist.txt (generated by tools/build-wordlist.ts)
    icons/          App icons (generated by tools/make-icons.ts)
    manifest.webmanifest
  typescript/
    index.ts          Startup: imports the CSS and calls startApp()
    app.ts            The game session: owns the current state, handles input, keeps the screen up to date
    serviceWorker.ts  Built separately, to dist/sw.js (offline play)
    global.d.ts       Additions to global types (`__BUILD_VERSION__`, CSS imports)
    types/            Plain-data types only, one per file (Puzzle, DayState, DaySummary, LifetimeStats, ...)
    data/             Fixed definitions / constants (app constants, the ranks, the list of badges)
    gamelogic/        Rules and calculations, with no DOM (except storage.ts and bookmarklet's currentGameUrl()):
      puzzle.ts           Choosing the day's puzzle, answers, scoring, ranks, checking guesses, hints
      day.ts              One day's play: load/save, which puzzle (generated or imported), locking
      stats.ts            Per-day summaries and all-time stats (streaks, ...)
      achievements.ts     Earning badges; achievementChecks.ts has what earns each one-off achievement
      nytImport.ts        Reading and checking imported puzzle data
      bookmarklet.ts      Making the bookmarklet
      dates.ts            Day keys and date arithmetic
      wordlist.ts         Loading the word list; letter masks
      prng.ts             Seeded random numbers (shared with the build tools)
      storage.ts          try/catch-wrapped localStorage
    ui/               Drawing and screens: the honeycomb, progress track, found-words box, modals, toasts, and each
                      screen (help, rankings, hints, yesterday, stats, settings, splash)
tools/              Node build tools (TypeScript, run through tools/run.cjs): build-wordlist.ts, make-icons.ts
tests/              Jest tests, mirroring src/typescript (plus tests/tools)
```

- Any code may import from `types/` and `data/`. Neither of them imports from `gamelogic/` or `ui/`.
- `ui/` imports from `gamelogic/` only for calculations it displays (ranks, hints, dates); it never changes saved
  state. Only `app.ts` changes the game's state and saves it.
- Tests in `/tests` mirror this layout.


## State

- The session's state (today's day and puzzle, the words found, the history, the badges, the typed word, the theme)
  lives in `app.ts`. Nothing else holds game state.
- Everything is **plain data** that survives JSON, apart from the `Puzzle`, which is rebuilt from the day each time
  (it is never saved): its answers are computed from the word list, or come from the imported puzzle stored with the
  day.
- Saved in localStorage, all prefixed `buzzoff:`:
    - `day:<YYYY-MM-DD>` - a `DayState`: which puzzle, the words found (with times), hints used, when Genius was reached
    - `history` - a `DaySummary` per day played, for the stats and badges
    - `achievements` - when each badge was earned
    - `theme` - the light/dark choice
- Values that can be worked out (score, rank, all-time stats) are **not** stored; they are calculated when needed.
  (`history` is the exception: it is a cache of each day's summary, so the stats don't need every day's puzzle rebuilt.)
- Every storage access is wrapped in try/catch: the game must work, without remembering anything, when storage is
  unavailable.


## The Daily Puzzle

- `data/puzzles.txt` lists the puzzles in the order they are played, one per line (center letter, then the 6 outer
  letters). Day N after `EPOCH_DAY` (2026-01-01) plays line N, starting over when the list runs out (~9 years).
- Answers are computed in the browser from `data/words.txt`, with 26-bit letter masks. So every device gets the same
  puzzle and answers, and nothing needs to be stored or fetched per day.
- Changing the word list changes the answers (including for past days in the history). Bump `WORDLIST_VERSION` in
  `data/app.ts` and change it deliberately.


## Build and Deploy

- `npm run build` type-checks, then webpack builds `dist/`: `index.html`, `app.bundle.js` (with the CSS), `sw.js`, and
  everything in `src/static/` (copied by a small plugin in `webpack.config.js`).
- The service worker's cache is named after the build (`__BUILD_VERSION__`), so each deploy installs a new worker and
  the page offers "Update available — Reload". It is skipped on localhost unless the address has `?sw`.
- All paths are relative, so the site works under `https://<user>.github.io/<repo>/`.
- `.github/workflows/deploy-pages.yml` lints, tests, builds and publishes `dist/` to GitHub Pages on each push to
  `main`.


## UI

- Styling lives in `src/css/styles.css`. Colors are tokens (CSS custom properties on `:root`); dark mode is a second
  set of the tokens, under `@media (prefers-color-scheme: dark)` and `[data-theme="dark"]` (the player can also force
  light or dark from the Menu). Any new color must be a token with a value in both.
- UI code gives elements classes and leaves the look to the CSS, rather than writing inline styles. The exceptions are
  values that come from the state (the progress track's positions, bar widths).
- Elements are made with the small `h()` helper in `ui/dom.ts`; there is no framework.
- Screens are modals (`ui/modal.ts`): one at a time, closed by Escape, the backdrop or the close button, with focus kept
  inside while open.


## General
- Do not store data on global variables (such as `window`) unless specifically told to or there is no other choice.
  When adding code to store data on a global variable, call it out in the chat
- Functions that calculate something take what they need as parameters and return the result; they don't read the
  session's state.
- No NYT data is ever committed, fetched automatically, or shared. The bookmarklet runs on the player's own device and
  passes the puzzle in the address's `#` (which never reaches a server); the game removes it from the address at once.
